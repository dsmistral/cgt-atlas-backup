# CGT Paper-Pattern Survey — project state

**What this is.** A sibling project of the CGT Atlas (see the `cgt-atlas-project` topic for the book and its P1–P42 Master Pattern Index): mining the primary literature of combinatorics & graph theory for load-bearing problem-solving patterns, chunk by chunk. Goals: (1) test the textbook-mined P-index against actual field practice, (2) give the silent forward-registry patterns (P20, P24, P27–P42) genuine usage evidence, (3) hunt for P43+ candidates via the load-bearing recurrence test.

**User-locked scope decisions (chunk 0, 2026-10-13):** corpus lives in the `papers/` subfolder of the `dsmistral/cgt-atlas-backup` GitHub repo (the Atlas set there is read-only for this survey); deep sweep, 126 seed papers in 13 thematic batches A–M; per-paper gathering = verified metadata + abstract/summary + decisive proof moves, fetching an open-access full text ONLY when a candidate new pattern lacks enough published detail to write teaching material from and a paywall-free copy exists.

## Resume protocol (for a new chat)

1. **Read this file first.**
2. **Open the ledger:** `github_app.get_file_contents` on `papers/STATE.md` in `dsmistral/cgt-atlas-backup` — it is the source of truth for which chunk is next. The full chunk protocol, per-paper template, and seed corpus are in `papers/README.md` and `papers/CORPUS.md`.
3. **Run one batch per session** (chunks 1–13): verify seed metadata against a web source (record the URL), gather the abstract or a faithful summary, extract the decisive moves, tag each with Atlas P-IDs, log candidate new patterns. **Work style v2 (user-directed 2026-10-13, after a retry lost nothing):** split each batch into sub-chunks of ~3 papers, each sub-chunk landed as its OWN `push_files` commit (gather -> per-paper files -> BATCH section -> STATE.md -> touched pattern dossiers -> INDEX -> push), so a retry never costs more than one sub-chunk. **Patterns layer:** `papers/patterns/` holds ONE dossier file per pattern (P1-P42) grouped into 11 family folders by similarity/interdependence, plus `candidates/` (CAND-/WATCH- files); dossiers quote the census/miss lines from batch files (batches stay the gather record). Charter and update rule: `papers/patterns/README.md`; per-pattern census: `papers/patterns/INDEX.md`. Then push everything in ONE `push_files` commit per sub-chunk.
4. **Light resume, no canvases:** this survey NEVER restores Atlas canvases into the work area. Resume = this file -> `papers/STATE.md` -> only the active batch file(s) and the pattern dossiers the session will touch. Do not bulk-read `papers/patterns/INDEX.md` or all dossiers; read dossier files only when a sub-chunk actually fires/misses that pattern.
5. **Chunk 14 = synthesis:** write `papers/ANALYSIS.md` — recurrence-tested candidates, proposed P43+ entries (load-bearing test: fires across ≥ 2 different batches), usage evidence for the silent P-IDs, honest coverage gaps. Build it FROM the pattern dossiers, not by re-reading batches.
6. **At close of every chunk session,** refresh the current-state paragraph below (extend, never rewrite history).

## Standing rules

- Push route: `push_files` only; never `create_or_update_file` for `papers/` files; no emoji or other astral characters in repo files under `papers/`.
- Extend, never rewrite: corrections to published batch files go in a correction log, never silent rewrites; session changes described in the commit message.
- Verification levels per Atlas convention: executed lab > complete proof > flagged sketch > formal track; each batch file records the level reached; web-sourced metadata carries its source URL.
- Seed rows in `CORPUS.md` are unverified until gather time; corrections and paper swaps are logged, never silent.
- Long sessions: prefer pushing small intermediate commits over keeping work local (files in /home/user do not survive restarts).
- This survey does not edit the Atlas; adopting any P43+ pattern into the Atlas is a future Atlas session requiring user approval, per the Atlas working protocol in the `cgt-atlas-project` topic.
