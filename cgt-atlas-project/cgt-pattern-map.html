The Pattern Map — the Companion Registry (P1–P45)

Part of the Combinatorics & Graph Theory Atlas (see the Atlas canvas for the chapter map and progress report). A companion artifact, not a chapter: the 21 chapter numbers stay pinned.

1 · What this file is

The Atlas groups problems by the move that solves them. The Master Pattern Index (cgt-atlas.md §1) assigns each recurring solution pattern an immutable identifier, P1 through P45. Across the 21 chapters the same pattern is introduced, taught, and invoked under chapter-local names — a chapter’s pattern table names it for its own material, a Trick Bag card names its face, an exercise hint names its cameo. This file is the one place that lists every identifier with its canonical name and every name the book has used for it, so identifiers stay uniform across all chapters.

It is built to be used as an immutable reference by automated validation or improvement pipelines (tools or AI): the P-ID is the join key, the names are documentation, and the machine-readable payload below is pinned by a SHA-1 hash. Registry version 1, generated 2026-10-15, extracted from the 21 chapter masters and the Atlas P-index. A sweep verified that no identifier outside P1–P45 appears anywhere in the masters.

2 · How a pipeline should consume it

  1. Locate the <pre id="registry-json"> block in section 5.
  2. HTML-unescape the entities (&amp;, &lt;, &gt;) to recover the JSON text.
  3. UTF-8 encode it and verify SHA-1 against the pin in section 5. If the hash does not match, do not trust the file.
  4. Parse the JSON. The id field ("P1" … "P45") is the sole join key; match chapter pattern-table rows, Trick Bag cards, and hint mentions on it.
  5. Treat canonical as the one official name; aliases and faces are documentation with chapter provenance — never keys.
  6. Per-pattern firing evidence (the usage ledger) lives in the Atlas master (cgt-atlas.md §1), not here; this registry carries only the naming map.
  7. If the Atlas ever adopts new patterns (P46+), this registry bumps its version and SHA-1 pin; the IDs of existing patterns never change.

3 · Registry conventions

  • IDs are the only keys. Pn, n = 1..45, immutable. One canonical name per ID.
  • Evidence vocabulary used with pattern mentions: GENUINE (the pattern carries the proof — Ch. 12’s per-problem map, Ch. 20’s census), PARTIAL (fires as a supporting step), named cameo (a one-off named appearance), forward-registry (introduced at its chapter’s ship, awaiting its first genuine use — see each pattern’s note).
  • Ship markers in labels: “(new this chapter)” = proposed to the registry at the chapter’s ship; “(this chapter’s home)” = the pattern’s home chapter; “(cameo)” = brief named appearance.
  • Compound rows: a chapter row may fire two patterns together — Ch. 3’s “P8 + P10 Extremal rod” and “P15 Greedy / P18 algorithmic”. Both IDs receive the alias, with the compound noted.
  • Name collision: P17 “Duality (min–max)” and P37 “Duality” (plane duals) are distinct patterns sharing one local name — exactly why the ID is the join key.
  • Deliberately outside the registry: Ch. 20’s game-strategy cluster and Ch. 21’s five coverage-gap engines are named clusters with no Atlas P-ID — do not force them into P1–P45.
  • Reading order lore (Ch. 12’s honest-census note): the pre-doctoral elementary five are P25, P4, P1, P9, P10; the honest boundary is P5, P16, P23, P30–P31 — master the elementary five first.
